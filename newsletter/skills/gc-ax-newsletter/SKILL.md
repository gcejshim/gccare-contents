# GC AX Studio · Newsletter

운영자가 올린 기획안으로 AX Studio · Newsletter의 세 메뉴(썸네일 · 콘텐츠 이미지 · PDF)에 넣을 내용을 만든다.

| 메뉴 | 만드는 것 | 자세한 규칙 |
|---|---|---|
| **뉴스레터 썸네일** | 콘텐츠마다 **그릴 것 키워드만** 담은 JSON 1개 (미리보기 없음) | `references/thumbnail.md` |
| (공통) 디자인 시스템 | 색 · 글자 · 모양 · 그래프 색 · 썸네일 프리셋 기준 | `references/design-system.md` |
| **콘텐츠 이미지** | 이미지 목록 확인 → 한 장씩 미리보기 → OK → 블록 JSON (`nl-block` / `nl-blocks`) | `references/content.md` |
| **PDF** | 기획서 쪽마다 블록 정리 → 확인 → 작업 내용 JSON (`nl-pdf`) 하나 | `references/pdf.md` |

## 진행 순서

1. 기획안에서 **호수**와 콘텐츠 목록(01 메인, 02 · 03 서브)을 찾아 먼저 보여 준다. **엑셀**이면 시트마다 내용을 읽어 어느 시트가 어느 콘텐츠 · 이미지인지 먼저 정리해 보여 주고, 표 · 수치는 셀 값 그대로 쓴다(반올림 · 단위는 원본 표시 형식대로, 계산이 필요하면 계산식과 결과를 같이 보여 주고 확인받기). 엑셀 안의 **그래프(차트)**는 그림을 옮기지 않고, 그래프가 가리키는 **데이터 범위 · 계열 이름 · 그래프 종류**를 읽어 편집기 그래프 템플릿(`hbar` · `vbar` · `line` · `donut` · `stack` · `pair`)으로 다시 만든다. 막대 → `vbar`/`hbar`, 꺾은선 → `line`, 원 · 도넛 → `donut`, 누적 막대 → `stack`. 그래프의 데이터 범위를 읽지 못하면 어느 셀을 쓸지 물어보거나 그래프 캡처를 받아 숫자를 확인받는다. 참고: 15호 = 2026년 10월, 이후 한 달에 한 호씩.
   **이미지만** 받았을 때(다른 곳 그래프 · 표 · 인포그래픽 캡처, 손그림 등): 이미지에서 글자 · 숫자를 읽어 **먼저 목록으로 보여 주고 맞는지 확인**받는다(잘못 읽을 수 있으므로, 흐린 숫자는 `?`로 표시하고 묻기). 확인되면 이미지의 **배치 · 순서 · 그래프 종류 · 강조 위치**는 따르고, **색 · 글꼴 · 크기 · 여백은 디자인 시스템**(`references/design-system.md`)으로 바꿔 편집기 템플릿으로 다시 만든다. 원본의 브랜드 색 · 일러스트는 옮기지 않는다. 원본에 GC Care 로고가 있으면 그림으로 옮기지 않고 블록 설정 `logo`(top · bottom)로 넣는다.
   **기획안 안에 들어 있는 썸네일 · 디자인 예시 그림은 '이미지만 받았을 때'가 아니다** — 문구 · 강조 · 분위기를 정하는 참고로만 쓰고, 그림을 따라 그리거나 HTML · 스크립트로 다시 만들지 않는다(`references/thumbnail.md`).
2. 사용자가 무엇을 원하는지 정한다.
   - "썸네일"이라고 하면 → `references/thumbnail.md`를 읽고 그대로 따른다.
   - "콘텐츠 이미지 · 블록 · 표 · 차트 · PC · 모바일"이라고 하면 → `references/content.md`를 읽고 그대로 따른다. 그냥 **"이미지 만들어줘"**도 콘텐츠 이미지로 본다.
   - "PDF · 자료실 · 실무 자료 · 체크리스트 PDF"라고 하면 → `references/pdf.md`를 읽고 그대로 따른다.
   - 예: "디자인 첨부하고 썸네일 만들어줘" → 그 콘텐츠 내용으로 그릴 것 키워드 JSON만(디자인을 따라 만들지 않음). "디자인 첨부하고 이미지 만들어줘" → 위 '이미지만 받았을 때' 방식으로 콘텐츠 블록 JSON.
   - 기획안만 주고 정하지 않으면 → "썸네일부터 할까요, 콘텐츠 이미지부터 할까요? (둘 다도 돼요)" 한 줄로 묻는다. 둘 다면 **썸네일 → 콘텐츠 이미지** 순서.
3. 두 메뉴 모두 **기획안 문구를 임의로 바꾸지 않는다.** 줄바꿈 · 강조만 정하고, 수치가 없으면 지어내지 않는다.
4. 결과는 썸네일 · 콘텐츠 이미지 · PDF 모두 **항상 아티팩트(코드 · JSON)**로 준다 — 길이와 상관없이 같은 방법(짧다고 채팅 코드 블록으로 주지 않기). 아티팩트 안에는 JSON만 넣어 [복사] 한 번으로 끝나게 한다. 채팅 답은 길이 제한으로 중간에 끊긴다. **다운로드 파일(.json 첨부)은 만들지 않는다** — 맥에서 다운로드 파일을 열어 복사하면 형식이 깨진다. 넣는 방법을 한 줄로 붙인다(각 references의 안내 문구). 아티팩트 종류는 **코드(언어 `json`)**로 만든다 — 그래야 창 위에 [복사] 버튼이 생긴다. HTML · React · 문서 아티팩트로 만들지 않는다(화면으로 그려져 [복사] 버튼이 없음).
5. **결과를 주는 모양은 셋 다 같다** (사용자 지정 — 형식이 다르면 헷갈림):
   - 장마다 **「01-1 미리보기」**(HTML 그림 — 글자가 잘 들어갔는지 보는 용도) → 사용자가 OK → **「01-1 JSON」**(코드 json, 복사는 이것만). PDF는 「PDF 미리보기」 · 「PDF JSON」. **썸네일은 키워드만이라 미리보기 없이 「썸네일 01 JSON」**만. 제목은 이 모양으로만.
   - **결과를 주기 전에 기획서와 대조하고, 결과마다 한 줄로 알린다** (썸네일 · 콘텐츠 이미지 · PDF 모두. 미리보기 대신 내용이 맞는지 확인하는 장치):
     `기획서와 대조: 행 7개 · 숫자 4개(2026년 8월 1일 · 500명 · 1,200억 · 4월 30일) 일치`
     - 세는 것: 행 · 항목 · 쪽 수, 숫자 · 날짜 · 금액 · % 전부, 고유명사. 문구는 줄바꿈 · 강조 말고 바꾸지 않았는지.
     - 다르거나 빠진 게 있으면 "일치" 대신 **무엇이 다른지** 적는다(예: "공시 기한 날짜가 기획서와 다름 — 확인해 주세요"). 일부러 줄이거나 나눈 곳도 적는다.
     - 흐리거나 읽기 어려웠던 숫자 · 글자는 `?`로 표시하고 묻는다(지어내지 않기).
   - JSON에는 항상 종류 표시 `kind`가 있다: 썸네일 `nl-thumb`, 콘텐츠 이미지 `nl-block` · `nl-blocks`, PDF `nl-pdf`.
   - 넣는 방법은 셋 다 같은 문장으로 시작한다: "[복사] → AX Studio · Newsletter **아무 화면에서 Ctrl+V** 하면 맞는 메뉴로 가서 들어가요." 뒤에 메뉴별로 할 일만 한 줄(각 references).
