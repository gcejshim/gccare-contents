# 카드뉴스 편집기 - 깃허브 연동 계획 정리

## 왜 이 작업을 하는가
- 카드뉴스 편집기(HTML 파일)에서 쓰는 **OpenAI(GPT) 이미지 생성 API 키**와 **프롬프트(스타일 지시문)**를 둘 다 보호하기 위함
- 지금은 각자 브라우저(localStorage)에 개인 API 키를 직접 입력해서 쓰는 방식 → 여러 명이 쓰려면 키를 나눠줘야 하고, 유출 위험이 있음
- API 키를 파일에 직접 넣으면 브라우저 개발자 도구에서 그대로 노출되므로 위험
- 프롬프트(SECTION_STYLE, SECTION_PROMPT, HEADER_PROMPT_A/B 등)도 지금은 `cardnews_editor03.js` 안에 base64로만 인코딩되어 있어서, 개발자 도구로 열어보면 누구나 원문을 쉽게 복원해서 볼 수 있는 상태 → 이것도 완전히 숨기고 싶음
- **팀원한테도 공개하고 싶지 않음.** 프롬프트를 서버 코드 파일 안에 그대로 적어두면, 그 코드가 올라간 깃허브 저장소에 접근 권한이 있는 팀원은 코드를 열어서 원문을 읽을 수 있음 → 코드가 아니라 "환경 변수"에 저장해서, 깃허브 저장소를 보는 사람도 원문을 못 보게 해야 함

## 최종 방향: API 키 + 프롬프트를 전부 Vercel 환경 변수에 숨기기
회사 공용 API 키와 이미지 스타일 프롬프트(지시문)를 **코드에 직접 적지 않고, 전부 Vercel 환경 변수(Environment Variables)에만** 저장한다. 깃허브에 올라가는 코드에는 `process.env.OPENAI_API_KEY`, `process.env.SECTION_PROMPT`처럼 "이름표"만 있고 실제 내용은 없다. 실제 값은 Vercel 웹사이트 설정 화면에만 존재하며, 그 화면은 윤성웅님 계정으로만 접근 가능하다.

편집기(브라우저)는 "사용자가 입력한 내용"만 서버로 보내고, 서버가 환경 변수에서 진짜 스타일 프롬프트를 꺼내 합친 뒤, 역시 환경 변수에서 꺼낸 API 키로 OpenAI를 호출한다.

이렇게 하면 보호 범위가 다음과 같이 완성된다.
| 보는 사람 | 프롬프트 원문이 보이나 |
|---|---|
| 편집기를 여는 아무나 (브라우저/개발자 도구) | 안 보임 |
| 깃허브 저장소에 접근 권한이 있는 팀원 | 안 보임 (코드에는 이름표만 있음) |
| Vercel 계정 소유자(윤성웅님) | 설정 화면에서 확인 가능 |

**"개인 API 키 직접 입력" 예비 기능은 완전히 제거한다.** (이 기능을 남겨두면 그 경로에서는 프롬프트가 브라우저에 그대로 노출되어, 프롬프트 보호 목적과 상충하기 때문)

### 대상 파일
- `cards/cardnews_editor03.html` — 편집기 본체 (03 버전, 회사에서 계속 작업 중인 파일)
- `cards/cardnews_editor03.js` — 이미지 생성 함수들이 들어있는 스크립트 (편집기 전용, 내보낸 파일에는 포함 안 됨)

### 코드 변경 내용 (구현 계획)

**1. `api/generate-image.js` (신규, 저장소 루트 `api/` 폴더)**
Vercel이 자동 인식하는 서버리스 함수. 스타일 프롬프트(SECTION_STYLE, SECTION_PROMPT, HEADER_PROMPT_A, HEADER_PROMPT_B)는 코드에 적지 않고 **환경 변수에서 읽어와서** 조립하고, 클라이언트가 보낸 "사용자 입력 + 참조 이미지"와 합쳐 완성된 프롬프트를 만든 뒤, 역시 환경 변수인 진짜 API 키(`process.env.OPENAI_API_KEY`)로 OpenAI를 대신 호출한다.

- 요청 바디(클라이언트 → 서버): `{ target: 'header' | 'section', prompt, refImageDataURL, styleRefImages, headerRefImages, refGuidelines, activeHeaderStyle }` — 원본 스타일 지시문은 포함하지 않음
- 서버가 `target`에 따라 `process.env.SECTION_STYLE + process.env.SECTION_PROMPT` 또는 `process.env.HEADER_PROMPT_A` / `process.env.HEADER_PROMPT_B` 중 하나를 읽어와 완성된 프롬프트를 조립 (원문 텍스트는 코드 어디에도 없고 Vercel 환경 변수에만 존재)
- 조립한 뒤 `https://api.openai.com/v1/responses`에 요청하고, 응답을 클라이언트로 그대로 반환

**2. `package.json` (신규, 저장소 루트)**
Vercel이 프로젝트로 인식하도록 하는 최소 파일 (빌드 없음).
```json
{ "name": "gccare-contents", "version": "1.0.0", "private": true }
```

**3. `cards/cardnews_editor03.js` 수정**
- `SECTION_STYLE`, `SECTION_PROMPT`, `HEADER_PROMPT_A`, `HEADER_PROMPT_B` 상수와 그걸 조립하는 로직을 전부 **삭제**하고 서버(`api/generate-image.js`)로 이전
- `generateWithGPTSection(prompt)` / `generateWithGPT(prompt)`는 프롬프트를 직접 조립하지 않고, 참조 이미지와 사용자 입력만 모아서 `PROXY_URL`로 전송하는 역할만 하도록 축소
- `apiKey` 매개변수, `Authorization` 헤더, OpenAI 직접 호출 코드 전부 제거 (프록시 경유만 남김)

**4. `cards/cardnews_editor03.html` 수정**
- API 키 입력 UI 전체 제거: `input#key-openai`, `button#key-openai-clear`, `button#key-openai-save`
- 관련 함수 전부 제거: `getOpenAIKey()`, `saveApiKeys()`, `clearApiKey()`, `updateKeyUI()`
- `generateAIImage()`에서 "API 키가 없으면 경고창 띄우고 중단"하던 블록 제거 → 키 개념 자체가 없어지므로 바로 서버 경유 진행

## IT 보안 관련 참고
- 사내 IT 인프라 보안 정책이 외부 클라우드 서비스 사용에 까다로울 수 있다는 이야기가 있었음
- 결정: 일단 Vercel(무료)로 먼저 써보고, 사용량/보안 검토 결과에 따라 나중에 회사 내부 서버로 옮길지 판단하기로 함
- 만약 내부 서버로 옮겨야 한다면, `api/generate-image.js`의 로직(요청을 받아서 프롬프트 조립 + 진짜 API 키를 붙여 OpenAI에 전달)은 거의 그대로 옮길 수 있음 — Vercel 전용 코드가 아니라 일반 Node.js 서버 코드로도 동작하는 구조

## 배포 절차 (순서대로)
1. 위 코드 변경을 깃허브에 커밋/푸시
2. vercel.com에서 깃허브 계정으로 로그인 → "New Project" → `gcejshim/gccare-contents` 저장소 import
3. Vercel 프로젝트 설정 → Environment Variables에서 아래 값들 등록
   - `OPENAI_API_KEY` = 실제 OpenAI 키 값
   - `SECTION_STYLE`, `SECTION_PROMPT`, `HEADER_PROMPT_A`, `HEADER_PROMPT_B` = 실제 프롬프트 원문 (지금 `cardnews_editor03.js`에 base64로 있는 내용을 디코딩해서 등록)
4. Vercel이 자동 배포 → 배포된 주소(예: `https://gccare-contents.vercel.app`) 확인
5. 그 실제 주소를 `cardnews_editor03.js`의 `PROXY_URL`에 반영하고 다시 커밋/푸시

## 참고 / 향후 고려 사항 (이번 범위 아님)
- 지금 설계된 프록시는 인증 없이 URL만 알면 누구나 호출 가능 (CORS `*` 허용). 내부용이라 당장은 괜찮지만, 남용이 우려되면 나중에 간단한 접근 비밀번호(shared secret) 체크를 추가할 수 있음
- 사용 기록(구글 시트 연동)은 이후 별도 단계로 진행
