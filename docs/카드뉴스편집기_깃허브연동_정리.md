# 카드뉴스 편집기 - 깃허브 연동 계획 정리

## 왜 이 작업을 하는가
- 카드뉴스 편집기(HTML 파일)에서 쓰는 **OpenAI(GPT) 이미지 생성 API 키**를 보호하기 위함
- 지금은 각자 브라우저(localStorage)에 개인 API 키를 직접 입력해서 쓰는 방식 → 여러 명이 쓰려면 키를 나눠줘야 하고, 유출 위험이 있음
- API 키를 파일에 직접 넣으면 브라우저 개발자 도구에서 그대로 노출되므로 위험

## 최종 방향: 키를 서버 뒤에 숨기기 (Vercel 프록시)
회사 공용 API 키는 **Vercel 서버리스 함수**에만 두고, 편집기는 그 서버를 거쳐서만 이미지를 생성하도록 바꾼다.
기존에 있던 "개인 API 키 직접 입력" 창은 예비 수단으로 그대로 남겨둔다 (키를 입력하면 예전처럼 직접 호출, 비워두면 자동으로 서버 경유).

### 대상 파일
- `cards/cardnews_editor03.html` — 편집기 본체 (03 버전, 회사에서 계속 작업 중인 파일)
- `cards/cardnews_editor03.js` — 이미지 생성 함수들이 들어있는 스크립트 (편집기 전용, 내보낸 파일에는 포함 안 됨)

### 코드 변경 내용 (구현 계획)

**1. `api/generate-image.js` (신규, 저장소 루트 `api/` 폴더)**
Vercel이 자동 인식하는 서버리스 함수. 클라이언트가 보낸 OpenAI 요청을 그대로 받아서, 서버에만 있는 진짜 API 키(`process.env.OPENAI_API_KEY`)를 붙여 OpenAI에 대신 요청하고 응답을 그대로 돌려준다.

```js
export default async function handler(req, res) {
  res.setHeader('Access-Control-Allow-Origin', '*');
  res.setHeader('Access-Control-Allow-Methods', 'POST, OPTIONS');
  res.setHeader('Access-Control-Allow-Headers', 'Content-Type');
  if (req.method === 'OPTIONS') return res.status(200).end();
  if (req.method !== 'POST') return res.status(405).json({ error: 'Method not allowed' });

  try {
    const openaiResp = await fetch('https://api.openai.com/v1/responses', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${process.env.OPENAI_API_KEY}`
      },
      body: JSON.stringify(req.body)
    });
    const data = await openaiResp.json();
    res.status(openaiResp.status).json(data);
  } catch (e) {
    res.status(500).json({ error: e.message });
  }
}
```

**2. `package.json` (신규, 저장소 루트)**
Vercel이 프로젝트로 인식하도록 하는 최소 파일 (빌드 없음).
```json
{ "name": "gccare-contents", "version": "1.0.0", "private": true }
```

**3. `cards/cardnews_editor03.js` 수정**
- 상단에 `PROXY_URL` 상수 추가 (배포 후 실제 Vercel 주소로 교체)
- `generateWithGPTSection` / `generateWithGPT`에 중복된 fetch 로직을 `callOpenAIResponses(body, apiKey)` 공용 함수로 정리
  - 개인 키가 있으면 → OpenAI 직접 호출 (기존 방식 그대로)
  - 개인 키가 없으면 → `PROXY_URL`로 호출 (서버가 대신 키를 붙여서 요청)

**4. `cards/cardnews_editor03.html` 수정 (아직 미적용)**
- `generateAIImage()` 함수에서 "API 키가 없으면 경고창 띄우고 중단"하던 부분 제거 → 키가 없어도 정상적으로 서버 경유 방식으로 진행되도록
- 키 입력창(`key-openai` input, 저장/삭제 버튼)은 그대로 유지 (예비용)

## 배포 절차 (순서대로)
1. 위 코드 변경을 깃허브에 커밋/푸시
2. vercel.com에서 깃허브 계정으로 로그인 → "New Project" → `gcejshim/gccare-contents` 저장소 import
3. Vercel 프로젝트 설정 → Environment Variables에서 `OPENAI_API_KEY` = 실제 OpenAI 키 값 등록
4. Vercel이 자동 배포 → 배포된 주소(예: `https://gccare-contents.vercel.app`) 확인
5. 그 실제 주소를 `cardnews_editor03.js`의 `PROXY_URL`에 반영하고 다시 커밋/푸시

## 참고 / 향후 고려 사항 (이번 범위 아님)
- 지금 설계된 프록시는 인증 없이 URL만 알면 누구나 호출 가능 (CORS `*` 허용). 내부용이라 당장은 괜찮지만, 남용이 우려되면 나중에 간단한 접근 비밀번호(shared secret) 체크를 추가할 수 있음
- 사용 기록(구글 시트 연동)은 이후 별도 단계로 진행
